EASYWAY API — ESPACE AGENCES (ORGANISATIONS) — FRONTEND INTEGRATION REFERENCE
Covers phases 1 and 2 of the "Espace Agences" analysis: organisations
(travel agencies + fleet managers), members and roles, invitations, drivers,
vehicles, dashboard, activity log. Two consumers:
  - the AGENCY PORTAL (separate web app)       -> /api/org/...
  - the EasyWay BACK-OFFICE (staff only)       -> /api/staff/organisations/...
Written against the code as of 07/10/2026 (app `organisations`). The schema
(/api/docs/, tags "Organisation*" and "Staff Organisations") is the reference.

Base path: /api/   Content-Type: application/json
Auth: Authorization: Bearer <access>  (same JWT as the rest of the API)
No HMAC signature on /api/org/ and /api/staff/ (browser apps).
Enum VALUES stay in French (VOYAGE, PROPRIETAIRE, ACTIF...), like the rest of the API.

------------------------------------------------------------
READ THIS FIRST

  1. Staff creates the organisation + its owner from the back-office.
  2. The owner gets an email: <PORTAIL_AGENCE_URL>/activer?uid=...&token=...
     (valid 72 h). The portal's /activer page posts uid + token + new password
     to org/invitations/accept/ and receives login tokens directly.
  3. Later logins: the usual POST auth/login/ with PHONE + password
     (the phone is the login id, the email only receives the link).
  4. On every portal load: GET org/me/ -> organisation + role -> pick menus.
  5. The organisation is ALWAYS the caller's own: there is no organisation id
     in any /api/org/ URL. An id belonging to another agency answers 404.

Roles (lowest -> highest): LECTEUR < GESTIONNAIRE < ADMIN < PROPRIETAIRE

  | Action                                   | LECTEUR | GESTIONNAIRE | ADMIN | PROPRIETAIRE |
  | read dashboard, profile, members, fiches |   yes   |     yes      |  yes  |     yes      |
  | create/edit/archive drivers & vehicles   |   no    |     yes      |  yes  |     yes      |
  | edit agency profile, invite/edit members |   no    |     no       |  yes  |     yes      |
  | read activity log                        |   no    |     no       |  yes  |     yes      |
  | transfer ownership                       |   no    |     no       |  no   |     yes      |
  The owner can never be edited/removed by anyone; ownership moves only by
  transfer (make-owner).

403 bodies on /api/org/ (show `detail`; branch on the situation):
  - not a member / member deactivated   -> "You are not a member of an active organisation."
  - organisation SUSPENDUE              -> "This organisation is suspended. Contact EasyWay."
  - organisation EN_ATTENTE             -> "This organisation is not active yet."
  - role too low                        -> "This action requires the <ROLE> role or higher."

Lists marked (paginated) answer { count, next, previous, results: [...] },
?page=&page_size= (default 20, max 100).

------------------------------------------------------------
1. AGENCY PORTAL — /api/org/

POST org/invitations/accept/          (public, no token)
  { "uid": "...", "token": "...", "new_password": "..." }
  200 { user, tokens: {access, refresh}, organisation }   -> store tokens, go to dashboard
  400 "Invalid or expired link."  (used, expired after 72 h, or wrong) -> ask an admin to resend
  400 { "new_password": [...] }   (Django password rules: 8+ chars, not too common...)

GET org/me/
  { "organisation": {...}, "member_id": "uuid", "role": "ADMIN" }

Organisation object:
  { id, type: VOYAGE|FLOTTE, legal_name, trade_name, rccm, niu, city, address,
    phone, email, status: EN_ATTENTE|ACTIVE|SUSPENDUE, plan: GRATUITE|PRO, created_at }

GET   org/profile/        -> Organisation
PATCH org/profile/        (ADMIN) trade_name, rccm, niu, city, address, phone, email
                          (type, legal_name, plan are staff-only; sent values are ignored)

GET org/dashboard/?days=30          (days: 0-180, default 30)
  { "members": 4,
    "drivers":  { "ACTIF": 12, "INACTIF": 1 },
    "vehicles": { "ACTIF": 9, "MAINTENANCE": 1, "INACTIF": 0 },
    "deadlines": [ { "kind": "INSURANCE"|"INSPECTION"|"LICENSE",
                     "target_type": "vehicle"|"driver", "target_id": "uuid",
                     "label": "LT123AB" | driver name,
                     "expires_on": "2026-10-05", "expired": true }, ... ] }
  deadlines = already expired OR within `days`, soonest first.

GET org/journal/        (ADMIN, paginated)
  results: { id, actor, action, target_type, target_id, details, created_at }
  action examples: membre.invite, membre.invitation_acceptee, chauffeur.cree,
  vehicule.modifie, organisation.suspendue ...

--- Members
GET  org/members/                  -> [Member]   (not paginated)
  Member: { id, full_name, phone, email, role, active, invited_at,
            accepted_at (null = invitation pending), invited_by }
POST org/members/                  (ADMIN)
  { "full_name", "phone", "email", "role": ADMIN|GESTIONNAIRE|LECTEUR }
  201 Member. Phone or email already known to EasyWay -> that account is
  attached directly (accepted_at set, no email link, they log in as usual).
  400 when: phone and email belong to two different accounts; the person
  already belongs to an organisation; role PROPRIETAIRE.
  Rate limit: 30 invitations / hour.
PATCH  org/members/{id}/           (ADMIN) { "role"?, "active"? }   owner -> 400
DELETE org/members/{id}/           (ADMIN) 204; the person's EasyWay account stays. owner -> 400
POST   org/members/{id}/resend-invitation/   (ADMIN) 200 | 400 if already activated
POST   org/members/{id}/make-owner/          (PROPRIETAIRE) target becomes owner,
                                             caller becomes ADMIN. Target must be
                                             active and activated.

--- Drivers (fiches; no link to the mobile app yet)
GET  org/drivers/?search=&status=   (paginated; default hides ARCHIVE)
POST org/drivers/                   (GESTIONNAIRE)
GET | PATCH org/drivers/{id}/       (PATCH: GESTIONNAIRE)
DELETE org/drivers/{id}/            (GESTIONNAIRE) archives + unassigns vehicles -> 204
  Driver: { id, full_name*, phone, license_number, license_category,
            license_expires_on (YYYY-MM-DD), status: ACTIF|INACTIF,
            vehicles: ["LT123AB", ...] (read-only), created_at }
  phone is normalised to +237... ; invalid -> 400.

--- Vehicles
GET  org/vehicles/?search=&status=  (paginated; default hides ARCHIVE)
POST org/vehicles/                  (GESTIONNAIRE)
GET | PATCH org/vehicles/{id}/      (PATCH: GESTIONNAIRE)
DELETE org/vehicles/{id}/           (GESTIONNAIRE) archives -> 204
  Vehicle: { id, plate*, type*: VOITURE|MOTO|TAXI|CAMION|BUS|UTILITAIRE,
             make, model, seats, insurance_expires_on, inspection_expires_on,
             status: ACTIF|MAINTENANCE|INACTIF, driver_id, driver_name (read-only),
             created_at }
  plate is normalised ("lt 123-ab" -> "LT123AB") and unique within the agency.
  driver_id must be a non-archived driver of the SAME agency, else 400.
  Assign / unassign = PATCH { "driver_id": "<uuid>" | null }.

2. EASYWAY BACK-OFFICE — /api/staff/organisations/  (is_staff)

GET  staff/organisations/?search=&type=&status=&page=   (paginated)
POST staff/organisations/
  { "type": "VOYAGE", "legal_name": "Buca Voyages SARL", "trade_name"?, "rccm"?,
    "niu"?, "city": "Douala", "address"?, "phone"?, "email"?, "plan"?,
    "waitlist_id"?: "<waitlist entry uuid>",
    "owner": { "full_name", "phone", "email" } }
  201 organisation detail (below). New owner -> status EN_ATTENTE + email link;
  owner already has an EasyWay account -> attached, status ACTIVE at once.
  waitlist_id: the entry is linked and marked contacted (converting it twice -> 400).
  Prefill this form from GET staff/waitlist/ entries with profile AGENCE_VOYAGE / FLOTTE.
GET   staff/organisations/{id}/   -> Organisation + members: [Member] + drivers_count + vehicles_count
PATCH staff/organisations/{id}/   profile fields + type + legal_name + plan
POST  staff/organisations/{id}/suspend/      -> SUSPENDUE (members get 403 on /api/org/)
POST  staff/organisations/{id}/reactivate/   -> ACTIVE (EN_ATTENTE if the owner never activated)
POST  staff/organisations/{id}/members/{member_id}/resend-invitation/
GET   staff/organisations/{id}/journal/      (paginated)

4. PHASE 3 — FLEET TRACKING (vehicles, live position, speeding, driver reports)

Principle: an organisation only ever sees trips its driver DECLARED with one
of its vehicles. Personal trips stay private (no organisation, no live
position stored).

Linking a driver to the app: the agency's driver record (org/drivers/) is
linked automatically to the EasyWay account with the SAME phone number --
when the record is created/edited, or when that person signs up later.
Driver objects now carry `app_account`: null (no EasyWay account with this
phone yet) | { "linked": true, "name": "..." }.

--- MOBILE APP (signed with HMAC like the rest of the mobile API)

GET users/me/vehicles/
  [ { "id": "uuid", "plate": "LT123AB", "type": "BUS", "make": "Toyota",
      "model": "Coaster", "organisation": { "id": "uuid", "name": "Buca Voyages" },
      "driver_id": "uuid", "assigned": true }, ... ]
  Vehicles in service (status ACTIF) of the agencies where the caller has an
  ACTIVE driver record. `assigned` vehicles come first: preselect it.
  EMPTY LIST = the user drives for no agency -> do not show the vehicle picker.

POST trips/   (existing endpoint) -- new optional field:
  "vehicle_id": "<uuid from users/me/vehicles/>" | null
  null/absent = personal trip. An id the caller may not drive -> 400
  { "vehicle_id": ["This vehicle is not available to you ..."] }.
  UX: before "Start", if users/me/vehicles/ is not empty, ask
  "Which vehicle are you driving?" (preselected = assigned one) with a
  "Personal trip" option.

POST telemetry/positions/   (existing) -- nothing changes for the app. For a
  trip declared with a vehicle the server additionally keeps the last
  position (live map) and detects speeding. Keep sending speed_kmh and
  heading: without speed_kmh no speeding can be detected.

POST incidents/   (existing) -- nothing changes. A report made while the
  author has an ACTIVE trip with a vehicle is attached to that trip and
  becomes visible to the agency.

--- AGENCY PORTAL /api/org/  (all roles can read)

GET org/live/                  vehicles on the road (ACTIVE trip, position < 15 min)
  [ { trip_id, vehicle: {id, plate, type}, driver: {id, name, phone},
      lat, lon, speed_kmh, heading, updated_at, origin_label,
      destination_label, started_at } ]       -> poll every 10-15 s
GET org/trips/?vehicle=&driver=&date_from=&date_to=&status=   (paginated)
  Trip: { id, vehicle, driver, origin_label, destination_label, status,
          started_at, ended_at, planned_distance_m, planned_duration_s,
          actual_distance_m, actual_duration_s, rating, telemetry: {
          batches, positions, avg_speed_kmh, max_speed_kmh, distance_m,
          first_at, last_at, duration_s }, speeding_count, reports_count }
GET org/trips/{id}/            Trip + origin, destination, geometry [[lat,lon]...],
                               last_position, speeding: [Speeding], reports: [Report]
GET org/speeding/?vehicle=&driver=&date_from=&date_to=        (paginated)
  Speeding: { id, trip_id, vehicle, driver, limit_kmh, max_speed_kmh, over_kmh,
              zone_name ("" = default limit), lat, lon, positions,
              started_at, ended_at, duration_s }
  Rule: limit = most restrictive active speed zone within 30 m, else 60 km/h;
  speeding when speed > limit + organisation.speed_tolerance_kmh (default 5,
  editable in PATCH org/profile/). Consecutive positions < 60 s apart = one episode.
GET org/reports/?vehicle=&driver=&date_from=&date_to=         (paginated)
  Report: { id, type, type_label, subtype, street_name, city, status,
            confirmations, disputes, lat, lon, trip_id, vehicle, driver, created_at }
GET org/badges/                { unread_notifications, latest_notification,
                                 vehicles_on_road, speeding_today }  -> poll every 30 s
GET org/notifications/?unread=1&page=     (paginated, + unread_count)
  { id, type: EXCES_VITESSE|SIGNALEMENT|ECHEANCE, title, text, link, created_at, read }
  One speeding notification per trip per 15 min (not one per episode).
POST org/notifications/{id}/read/   POST org/notifications/read-all/
GET org/dashboard/  -> now also "fleet": { on_road, trips_today, trips_7d,
  speeding_7d, reports_7d, top_speeding_drivers: [{driver_id, name, count}],
  drivers_with_app }
Organisation object: + speed_tolerance_kmh (0-30).

--- EASYWAY STAFF ACTING ON AN AGENCY

Every /api/org/ endpoint also accepts a staff user (is_staff) with the header
  X-EW-Organisation: <organisation uuid>
-> same answers as an ADMIN of that agency (not owner-only actions), even when
the agency is suspended or pending. Actions are logged under the staff
member's name. Used by the back-office "Organisations" section.

--- AGENCY PORTAL = THE BACK-OFFICE

The agency space now lives inside the back-office (/agence for members,
/organisations/{id} for staff). Invitation links point to
<PORTAIL_AGENCE_URL>/activer -> set PORTAIL_AGENCE_URL to the back-office URL.
