5. NOUVEAU — lieux sur la carte et pendant la navigation (16/10/2026)

EasyWay (back-office), + etablissements (HOPITAL, GARAGE...) marques
"visible sur la carte". Les lieux importes d'OpenStreetMap restent dans la
recherche seulement (trop nombreux pour la carte).
Chaque point :

    "category_label", "address", "neighborhood", "city", "lat", "lon" }
  kind=place -> fiche : GET /api/places/{id}/

  GET /api/places/map/?min_lat=&min_lon=&max_lat=&max_lon=&categories=a,b
    Carte d'accueil : rectangle visible (cote <= 50 km, meme regle que

  POST /api/places/along-route/
    { "geometry": "<routes/calculate -> geometry (polyline6)>",

    Pendant la navigation : meme usage que speed-zones/along-route (un appel

       (position_m - distance deja parcourue).

  GET /api/places/map/categories/
    [ { "category", "label", "count", "kind" } ]  -- pour les filtres de la carte.

6. NOUVEAU — meilleur itineraire en cours de route (19/10/2026)

Pendant la navigation, le serveur peut proposer une route plus rapide quand
un bouchon se forme (vitesses mesurees des conducteurs EasyWay + embouteillages
signales, deja pris en compte par le calcul d'itineraire).

  POST /api/trips/{id}/better-route/      (trajet ACTIF de l'appelant)
    { "lat", "lon", "heading"?, "remaining_waypoints"?: [{lat, lon}, ...] }
    -> toutes les 1-2 min pendant la navigation (limite : 120 appels/heure).
    { "reason": "BETTER_FOUND" | "NO_BETTER" | "NO_ALTERNATIVE" | "OFF_ROUTE" | "NO_ROUTE",
      "better_route": <meme forme qu'un element de routes/calculate> | null,
      "current_duration_s", "new_duration_s", "time_saved_s" }
    BETTER_FOUND : proposer "Itineraire plus rapide : -7 min via ..." (label),
      le conducteur accepte ou ignore -- jamais de changement automatique.
      Seuil : au moins 2 min ET 10 % du temps restant gagnes.
    OFF_ROUTE : le conducteur a quitte sa route -> recalcul classique via
      routes/calculate (comme aujourd'hui).

  POST /api/trips/{id}/switch-route/      (le conducteur accepte)
    { "lat", "lon", "route": <better_route tel quel> }   -> 200 Trip
    Le trace garde la partie deja parcourue + la nouvelle route. Ensuite :
    guider sur route.maneuvers et redemander speed-zones/along-route et
    places/along-route avec la nouvelle geometry.

7. NOUVEAU — itineraires voiture / moto alourdis par les signalements (20/10/2026)

  POST /api/routes/calculate/  -- deux champs facultatifs en plus :
    "vehicle_type": "VOITURE"|"MOTO"|"TAXI"|"CAMION"|"BUS"|"UTILITAIRE"
        (defaut : le vehicule du profil ; le conducteur peut en changer pour ce trajet)
    "vehicle_id": "<uuid de users/me/vehicles/>"  -- vehicule d'agence : son type prime.
  Moteur de calcul : moto -> "motorcycle" (pistes et rues etroites acceptees,
  ignore le trafic en direct mesure sur les voitures) ; voiture/taxi -> "auto" ;
  camion/utilitaire -> "truck" ; bus -> "bus".

  Chaque itineraire renvoye porte en plus :
    "vehicle_type": "MOTO",
    "delay_from_reports": 390,          // secondes ajoutees par les signalements
    "reports_applied": [ { "id", "type", "subtype", "delay", "applied_as": "delay" } ]
  "duration_with_traffic" inclut ce retard : c'est la duree a afficher.
  L'ordre de la liste et "is_recommended" suivent cette duree finale (a moins
  d'1 min d'ecart : le moins de signalements, puis le plus court).
  -> afficher "+6 min a cause de 2 signalements".

  Regles cote serveur :
    - un signalement compte s'il est a moins de 30 m du trace, dans le meme sens
      (cap a moins de 45 deg), pondere par sa fiabilite (votes) et son age ;
    - POLICE et RADAR : aucun effet (pas de detour pour eviter un controle) ;
    - route barree / inondation confirmee (2e auteur ou confirmation) : la route
      est evitee ; non confirmee : simple ralentissement. Inondation : evitee par
      une moto des le premier signalement ;
    - moto : 30 a 50 % du retard voiture selon le type (remonte les files).

  Renvoyer l'itineraire choisi tel quel a POST /api/trips/ (les champs ajoutes
  sont acceptes). Le type de vehicule est garde sur le trajet et reutilise par
  better-route (seuil desormais : 2 min ET 10 %).


8. CORRIGE — boucle / demi-tour au depart d'un itineraire (26/10/2026)

  POST /api/routes/calculate/ : nouveau champ optionnel
    origin_speed_kmh (float, km/h) : vitesse GPS au moment du calcul.

  Pourquoi : origin_heading oblige le calcul a partir dans cette direction.
  A l'arret, le cap GPS du telephone est faux -> l'itineraire partait parfois
  dans le mauvais sens puis faisait demi-tour (ex. Deido -> Bafoussam).

  Regles cote serveur :
    - origin_speed_kmh < 10 : origin_heading est ignore ;
    - origin_speed_kmh >= 10 : origin_heading est respecte ;
    - origin_speed_kmh absent : le serveur calcule aussi sans cap et garde ce
      resultat s'il est plus rapide d'au moins 2 min.

  A faire cote appli : envoyer origin_speed_kmh avec origin_heading, ou ne pas
  envoyer origin_heading quand la vitesse GPS est proche de 0.


9. NOUVEAU — noter un garage (27/10/2026)

  Seuls les garages se notent : lieu de categorie garage/mecanique (ex.
  "Garage / mecanique") ou etablissement de type GARAGE. Note 1 a 5 +
  commentaire facultatif (500 caracteres max). Un seul avis par utilisateur et
  par garage : renvoyer une note la remplace. Aucun point gagne.

  Reperer un garage : nouveaux champs dans places/map, places/along-route et
  GET /api/places/{id}/ :
    "is_garage": true, "rating_average": 4.2 | null, "rating_count": 12, "stars": 3.5 | null

  Etoiles a afficher : "stars" (0,5 a 5, par demi-etoile), PAS rating_average.
  stars tient compte du nombre d'avis : chaque garage part de 3 etoiles comme
  s'il avait deja 5 avis moyens, et les vrais avis l'emportent peu a peu.
    1 avis 5/5 -> 3,5 etoiles ; 20 avis 5/5 -> 4,5 ; 100 avis 5/5 -> 5
    1 avis 1/5 -> 2,5 etoiles ; 30 avis 1/5 -> 1,5
  Afficher aussi le nombre d'avis a cote : "3,5 ★ (1 avis)".

  GET /api/garages/{id}/reviews/?page=1          (public ; {id} = id du lieu
                                                   ou de l'etablissement)
    { "garage": {id, kind, name}, "average": 4.2 | null, "count": 12,
      "my_review": {id, rating, comment, status, ...} | null,   (si connecte)
      "count"/"next"/"previous"/"results": [
        {id, rating, comment, author_name | null, created_at, updated_at} ] }
    author_name est null si l'auteur est en mode invisible.

  POST /api/garages/{id}/reviews/                 (connecte)
    { "rating": 1-5, "comment": "..." }
    -> 201 (premier avis) ou 200 (modification) : l'avis + average/count/my_review
    Limite : 10 avis par heure. 404 si {id} n'est pas un garage.

  DELETE /api/garages/{id}/reviews/mine/          -> 204

  Un avis peut etre retire par la moderation : il sort de la moyenne ; son
  auteur le voit encore dans my_review avec status "RETIRE". Le modifier le
  republie.

11. NOUVEAU — telephone et position approximative des lieux (27/10/2026)

  Dans places/nearby, places/map, places/along-route et GET /api/places/{id}/ :
    "phone": "+237677123456"   format international, a composer tel quel
                               (tel:+237...) ; "" si inconnu, jamais null
    "position_approximate": true | false

  position_approximate = true : le lieu est au centre de son quartier, pas a
  son adresse (plusieurs lieux importes partagent exactement ce point, ex.
  69 lieux a Makepe en 4.03587, 9.7581). Ne pas proposer "Y aller" vers ce
  point (ou avec "Position approximative") ; "Appeler" reste valable.
  places/nearby classe d'abord les lieux bien places, par distance, puis les
  approximatifs, par distance.

  Les numeros sont encore rares : le fichier des lieux importes n'en contient
  aucun. Ils sont saisis depuis le back-office, ou viendront d'un nouvel
  import avec une colonne telephone.

  Avis des garages : c'est deja disponible, cf. section 9 (POST /api/garages/{id}/reviews/).
  Pour les etoiles, afficher "stars" (pas rating_average).


12. NOUVEAU — etat des routes, V1 (27/10/2026, spec ETAT_DES_ROUTES du 29/09)

  Note de 0 a 100 par tronçon d'environ 100 m, calculee chaque nuit (03:00) a
  partir des signalements (nids-de-poule, inondations, travaux, voie reduite,
  route glissante) et des vitesses mesurees de nuit (22 h - 5 h). Les chocs
  (accelerometre) sont la V2.
  Une route sans donnees est INCONNU, jamais BON.

  Carte :
    GET /api/road-conditions/?cells=<h3 res 8, max 50>    (public)
    [ { "segment_id": "123456:4", "geometry": "<polyline6>", "score": 32,
        "class": "MAUVAIS" | "DEGRADE" | null, "confidence": 0.6,
        "causes": ["NID_DE_POULE", "VITESSE"], "flood_prone": false,
        "updated_at": "..." } ]
    Seuls les tronçons DEGRADE/MAUVAIS et les inondables (class null s'ils ne
    sont pas degrades) sont renvoyes. Stable une heure : inutile de rappeler
    plus souvent. causes : sous-types de signalement, "VITESSE" (circulation
    ralentie de nuit). segment_id : "{arete du graphe}:{tranche}" (et non
    "{way_id}:{index}" comme dans la spec : le graphe ne donne pas la position
    dans la voie OSM) -- a traiter comme un identifiant opaque.

  Score du trajet, dans chaque element de POST /api/routes/calculate/ :
    "road_condition": { "good_m", "degraded_m", "bad_m", "unknown_m",
                        "flood_prone_m",
                        "worst": [ {segment_id, class, causes,
                                    distance_from_start_m} ] }   (3 au plus,
                                    dans l'ordre du trajet)
    good_m + degraded_m + bad_m + unknown_m = distance. Afficher unknown_m tel
    quel ("65 % en bon etat, 19 % inconnu"). null si indisponible (Valhalla).

  Au debut, presque tout sera "inconnu" : la vitesse de nuit demande 20
  passages de 5 conducteurs sur 60 jours, et les signalements 2 personnes.

  V3 -- "Eviter les routes degradees" (reglage utilisateur) :
    GET/PATCH /api/users/me/settings/ : nouveau booleen "avoid_degraded_roads"
    (false par defaut), a placer avec avoid_tolls / avoid_unpaved_roads.
    Active : les itineraires sont classes en penalisant les metres DEGRADE
    (vitesse x 0,8) et MAUVAIS (x 0,5) ; aucune route n'est interdite et la
    duree affichee reste la vraie. road_condition.avoid_penalty_s donne le
    temps de penalite retenu (pour debogage, pas a afficher).

14. NOUVEAU — points de repere dans le guidage (27/10/2026, spec du 26/10)

  Dans chaque manoeuvre de routes/calculate (donc aussi better-route) :
    "landmark": { "name": "Carrefour Ndokoti", "kind": "CARREFOUR" }
  kind : CARREFOUR, STATION, CULTE, SANTE, MARCHE, AUTRE. Champ ABSENT (pas
  null) quand il n'y a pas de repere sur -- et toujours absent au depart et a
  l'arrivee. Un seul repere par manoeuvre ; jamais le meme deux fois de suite.

  Choix cote serveur : lieux nommes a moins de 60 m du point de manoeuvre,
  visibles en arrivant (pas apres le virage), par priorite carrefour >
  station > culte > sante > marche > autre (banque, ecole, hotel...), puis le
  plus proche. Ecartes : lieux non valides, a position approximative (centre
  de quartier), noms de plus de 40 caracteres ou contenant ";".

  Renvoyer la route telle quelle a POST /api/trips/ et switch-route : le
  repere est garde avec les manoeuvres du trajet.

16. NOUVEAU — "je veux un autre itineraire" pendant le trajet (28/10/2026)

  better-route NE CONVIENT PAS a ce bouton : il ne propose qu'une route PLUS
  RAPIDE (au moins 2 min et 10 % de gain) et repond NO_BETTER sinon -- d'ou
  "pas d'autre chemin" sur Akwa Palace -> Total Bonateki.

  POST /api/trips/{id}/alternative-routes/     (trajet ACTIF de l'appelant)
    meme corps que better-route :
    { "lat", "lon", "heading"?, "remaining_waypoints"?: [{lat, lon}] }
  -> { "reason": "ALTERNATIVES_FOUND" | "NO_ALTERNATIVE" | "NO_ROUTE",
       "current_duration_s": 300 | null,
       "routes": [ <element de routes/calculate> + "time_difference_s": 240 ] }
  routes : toutes les routes DIFFERENTES de celle suivie, plus lentes
  comprises, de la plus rapide a la plus lente. time_difference_s = duree de
  la route - duree restante de la route suivie (positif = plus lente ;
  null si le conducteur a quitte sa route). Afficher par ex. "+4 min".
  Le conducteur choisit -> switch-route avec la route choisie (inchange).

  Les deux appels coexistent :
    better-route        automatique, toutes les 1-2 min : route plus rapide ?
    alternative-routes  a la demande du conducteur : autres routes, meme plus lentes.


17. AJOUT — points evites en cours de route (28/10/2026)
  better-route et alternative-routes acceptent maintenant le meme champ que
  routes/calculate :
    "avoid": [{"lat": ..., "lon": ...}]
  Envoyer les points evites par le conducteur : le recalcul les contourne.
  Si la route suivie passe par un point evite, better-route repond OFF_ROUTE
  (refaire routes/calculate avec avoid) et alternative-routes renvoie toutes
  les routes qui le contournent (time_difference_s null).
  alternative-routes reste facultatif : l'appli peut aussi refaire
  routes/calculate depuis sa position et ecarter elle-meme la route suivie.
